## 🔧 Configuration

### Language Switching
Each README file includes language switch links:
```markdown
**Language**: [English](README-EN.md) | [Chinese](README.md)
```

### Contact Information (i18n)
Contact details are consistent across language versions so users worldwide can get support.

## 📝 Content Synchronization

### Update Workflow
1. Update the Chinese README.md
2. Sync updates to the English README-EN.md
3. Update the GitHub homepage display document
4. Ensure all links and contact information are correct

### Translation Principles
- **Accuracy**: Ensure technical terms are translated correctly
- **Consistency**: Keep terminology consistent across translations
- **Localization**: Consider usage habits of users in different locales
- **Completeness**: Ensure every feature has corresponding documentation

## 🌐 i18n Best Practices

### 1. Technical Terms
- Keep English originals: API, Docker, Redis, etc.
- Chinese translations where appropriate: database, cache, container, etc.
- Mixed usage when natural: Docker container, Redis cache, etc.

### 2. Code Examples
- Keep code unchanged
- Use comments in the target language
- Keep variable names in English

### 3. Links and Contact
- Keep links unchanged
- Use English for contact methods (email, GitHub, etc.)
- Use the appropriate platform for community groups

### 4. Images and Badges
- Use universal icons and badges
- Avoid images that contain text
- Prefer SVG for clarity at any scale
