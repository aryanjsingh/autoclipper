# Experience Sharing Video Timestamp Positioning Prompt

## Core Principles: Complete Experience, Clear Operation, Practical Value

1.  **Experience Completeness**: Timestamps must strictly correspond to complete experience sharing and method introductions.
2.  **Operational Coherence**: The time range must completely cover all key steps of an experience, ensuring complete operational logic.
3.  **Natural Boundaries**: Prioritize positioning timestamps at method transitions, technique switches, or natural boundaries of experience topics.

---

## Key Instructions: How to Determine `start_time` and `end_time`

### Determining `start_time`:
-   Should be positioned at the start time of the **first core introduction** sharing that experience.
-   Ignore irrelevant transitions, personal chat, or background setup before that introduction.
-   **Preferred Choice**: Start at the point where the experience topic is clearly stated, ensuring completeness of method introduction.
-   **Special Consideration for Experience Content**: If there is important background explanation or problem description, the start time should be moved earlier accordingly.

### Determining `end_time` (Most Important):
-   **Must be** the end timestamp of the **last sentence** covering the core sharing of that experience.
-   **Method Completeness**: Ensure that core content such as experience introduction, operational steps, and notes are complete without gaps in the method.
-   **Natural Ending**: Prioritize ending at summary statements, effect explanations, or experience transitions.
-   **Practice Point Inclusion**: If there are important practice points or notes at the end of the experience, they should be included.
-   If the experience sharing discussion continues to the end of the provided SRT text block, then `end_time` should be the end timestamp of the last relevant subtitle.
-   **Wrong Practice**: Mindlessly setting `end_time` to the end time of the entire text block. This must be absolutely avoided.

### Experience Content Duration Control Principles:
-   **Target Duration**: Each experience topic segment should be between 3-8 minutes
-   **Complex Method Duration**: Complex methods involving multi-step operations can be extended to 10 minutes
-   **Simple Techniques**: Clear and concise small techniques can be compressed to 2-3 minutes
-   **Systematic Methods**: Complete method systems or workflows can be extended to 12 minutes

### Special Handling for Experience Content:
-   **Operational Steps**: Methods containing multiple operational steps should preserve the entire process
-   **Case Illustrations**: Important practical cases and effect demonstrations should be treated as a whole
-   **Technique Key Points**: Core techniques and notes should appear together and not be separated
-   **Problem Solving**: Problem descriptions and solutions should be fully included

---

## Input Format
You will receive a JSON object containing:
-   `outline`: A JSON array containing **multiple** experience topics to process.
-   `srt_text`: A **single** SRT text block related to this batch of topics, formatted as `sequence number\nstart --> end\ntext\n\n`.

## Output Format
-   Strictly following the input outline structure, supplement each topic object with `start_time` and `end_time` fields.
-   **Key**: In the output, rename the input `title` field to `outline`, and rename the `subtopics` field to `content`.
-   Finally output a JSON array containing **all** processed topics.
-   Ensure the time format is `HH:MM:SS,mmm`.

**Strict JSON Output Requirements:**
1. Output must start with `[` and end with `]`; do not add any explanatory text, titles, or Markdown code block markers
2. Use standard English double quotes ", never use Chinese quotes "" or single quotes
3. Ensure all brackets and square brackets match correctly; objects are separated by commas, with no comma after the last object
4. Quotes within strings must be escaped as \"
5. Must not contain any comments, extra text, or control characters
6. Ensure the JSON is completely valid and can be parsed by a standard JSON parser

## Experience Content Timestamp Positioning Examples

### Correct Timestamp Positioning:
- **Method Introduction**: Starts from "Let me share a method..." and ends with "That's the entire operation process"
- **Technique Sharing**: Starts from "Here's a small tip..." and ends with "Pay attention to these key points"
- **Problem Solving**: Starts from "When you encounter this problem..." and ends with "The problem can be solved"

### Errors to Avoid:
- Breaking in the middle of operational steps
- Separating method introduction from practice points
- Truncating at key points of case illustrations
- Ignoring important notes or effect explanations

## Special Considerations for Experience Content

### 1. Operational Methods:
- Ensure complete operational steps and processes are included
- Preserve important operational key points and notes
- Include effect expectations and verification methods

### 2. Technique Sharing:
- Maintain the completeness and practicality of techniques
- Include applicable scenarios and usage conditions
- Ensure clear expression of technique key points

### 3. Problem Solving:
- Include the complete process of problem identification and solution
- Maintain the logic of the problem-solving approach
- Ensure verification explanation of the solution effect

### 4. Experience Summary:
- Preserve complete experience summary and reflection
- Include success factors and failure lessons
- Ensure the replicability explanation of the experience

## Notes

1. **Method Completeness**: Ensure each segment contains complete method introduction and operational key points
2. **Practical Value**: Important practical techniques and notes must be fully included
3. **Logical Coherence**: The logical chain of experience sharing should remain complete
4. **Operability**: Operational steps and practice points should be clear and complete
5. **Value Neutrality**: Maintain an objective stance during timestamp positioning without making value judgments on the experience
